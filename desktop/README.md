# UniversalAI Messenger — desktop-обёртка

Не переписывает мессенджер — открывает ту же страницу `/messenger`, что и браузер,
в нативном окне (Electron = тот же Chromium). Функционал идентичен: чаты, звонки,
реакции, боты, админ-панель — всё то же самое, включая CSP и WebRTC для LiveKit.

Единственное, чего не может обычная вкладка браузера — сообщать о присутствии,
когда окно закрыто. Это приложение решает именно это: закрытие окна прячет его
в трей вместо завершения процесса, страница продолжает жить в фоне.

## Как теперь работают статусы

Ничего не менялось ни в бэкенде, ни в веб-коде мессенджера — статус и так
считался по всем одновременным подключениям пользователя сразу (веб-вкладка +
десктоп), просто раньше закрыть = выйти. Теперь:

| Статус | Когда |
|---|---|
| **В сети** | окно открыто и активно (или activity-таймер не истёк) |
| **Отошёл** | окно свёрнуто в трей / не в фокусе дольше ~2 минут, но приложение запущено — то есть компьютер включён, а мессенджер просто не открыт на экране |
| **Не в сети** | приложение полностью закрыто через «Выход» в трее, либо компьютер выключен |

Если параллельно открыта веб-вкладка и она активна — статус «в сети» победит
(берётся самое «живое» из всех подключений), это тоже уже было в бэкенде.

Для того чтобы «отошёл» действительно отражал «комп включён», а не «когда я
последний раз вручную открыл приложение» — включите в трее пункт
**«Запускать при входе в систему»**.

## Первый запуск

1. Собрать зависимости и запустить в режиме разработки (нужен Node.js 18+ и npm
   на машине, где собираете/тестируете — этого нет в контейнерной среде проекта,
   ставится отдельно):
   ```bash
   cd desktop
   npm install
   npm start
   ```
2. При первом старте откроется окошко настроек — впишите адрес сервера (тот же,
   что открываете в браузере), например `https://192.0.2.8` (это и есть
   адрес по умолчанию — совпадает с `MESSENGER_ALLOWED_ORIGINS`/`MESSENGER_LIVEKIT_URL`
   в `.env` этого деплоя). Дальше приложение просто грузит `<адрес>/messenger`.
3. Сертификат у шлюза самоподписанный (см. `deploy/tls/`) — при первом
   подключении к новому адресу появится окно «Доверять этому сертификату?»
   с отпечатком. Это одноразово на адрес и запоминается — аналог того, как
   браузер один раз просит подтвердить исключение.
4. Если на сервере включён `PORTAL_SSO_REQUIRED=true`, окно автоматически
   переходит на страницу входа портала, затем возвращается в мессенджер.
   Сначала выдайте мессенджеру отдельный HTTPS-адрес и впишите его в настройках
   окна. Локальная форма `/login` в этом режиме отключена. При каждом новом
   открытии страницы мессенджера личность сверяется через портал.

Сменить адрес сервера позже: значок в трее → «Настройки сервера…».

## Сборка инсталляторов

```bash
npm run dist          # под текущую ОС
npm run dist:win      # NSIS-инсталлятор для Windows
npm run dist:mac      # DMG для macOS (macOS-сборку надёжно делать только на самой macOS)
npm run dist:linux    # AppImage + .deb
```
Результат — в `desktop/dist/`.

### «Чтобы все могли установить»

Инсталляторы соберутся и будут ставиться у любого пользователя, но без платного
сертификата подписи кода Windows (SmartScreen) и macOS (Gatekeeper) покажут
предупреждение «неизвестный издатель» при первом запуске — пользователю нужно
один раз нажать «Подробнее → Всё равно выполнить» (Windows) или через
Finder ПКМ → «Открыть» (macOS). Полностью убрать это предупреждение можно
только купив код-signing сертификат и подключив его в `build` секцию
`package.json` (`win.certificateFile`/`mac.identity`) — отдельная задача,
не связанная с кодом.

## Иконка

`build/icon.png` (1024×1024) — единственный файл, который нужен
`electron-builder`: он сам генерирует `.ico`/`.icns`/варианты под Linux при
сборке. Хотите другой логотип — просто замените этот файл тем же именем
и размером.
