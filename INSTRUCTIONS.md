# UniversalAI — инструкция по запуску и использованию

Корпоративный защищённый мессенджер.
Стек: Flask (вход, сессии, выдача токенов мессенджера) + FastAPI/WebSocket (мессенджер) + PostgreSQL + Redis + LiveKit (звонки) + ClamAV (антивирус вложений) + nginx (шлюз).

---

## 1. Запуск

### Требования
- Docker Desktop запущен.

### Поднять всё
```bash
docker compose up -d
```
Первый запуск создаст volume-ы, накатит SQL-схему (`schema.sql`) и Alembic-миграции мессенджера автоматически.

### Проверить
```bash
docker compose ps           # все сервисы должны быть healthy
docker compose logs -f app  # логи платформы
```

### Адреса
- **https://localhost/** — сразу открывает мессенджер (без входа — окно входа), самоподписанный сертификат — браузер попросит подтвердить исключение.
- **http://localhost:5000/** — тот же шлюз, редиректит на https.

### После правок кода — ОБЯЗАТЕЛЬНО пересборка
Код копируется в образ при сборке (`COPY . .` в Dockerfile), а не монтируется томом. Простой `restart` правки не подхватит:
```bash
docker compose build app messenger-api && docker compose up -d
```
Если правили только `deploy/nginx*.conf` — пересборка не нужна, но именно на этой машине Docker Desktop не всегда подхватывает изменённый bind-mount по `restart`/`nginx -s reload`, требуется полное пересоздание контейнера:
```bash
docker compose up -d --force-recreate gateway
```

### Остановить
```bash
docker compose down          # контейнеры вниз, данные (volumes) остаются
docker compose down -v       # ОСТОРОЖНО: удаляет и volume-ы (все данные)
```

## 2. Вход в систему

Страница `/login`, два способа:
- **«Корпоративный AD»** — логин/пароль проверяются напрямую в Active Directory (нужен настроенный `LDAP_*` в `.env`).
- **«Локальный аккаунт»** — тестовые учётки, заведённые из `.env` при старте:

| Логин | Роли |
|---|---|
| `admin` | admin — полный доступ, в т.ч. админ-панель мессенджера |
| `test` | user |
| `foory` | user |

Пароли задаются переменными `LOCAL_ADMIN_PASSWORD` / `LOCAL_TEST_PASSWORD` / `LOCAL_FOORY_PASSWORD` в `.env`. Паролей по умолчанию нет: пароль короче 12 символов или стандартный (`admin123`, `test123`…) — приложение не стартует; пустой — учётка не создаётся.

Логин из AD, совпадающий с локальной учёткой, войти не сможет: локальная учётка не может быть «захвачена» входом через AD или SSO.

### Синхронизация с Active Directory
Когда заполнены `LDAP_URI`, `LDAP_BASE_DN`, `LDAP_BIND_DN`, `LDAP_BIND_PASSWORD`, платформа раз в `LDAP_SYNC_INTERVAL_MIN` минут (по умолчанию 15) выгружает из AD всех сотрудников: ФИО, отдел (`department`), должность (`title`), почту, телефон, кабинет. Сотрудники появляются в мессенджере сразу, до первого входа. Отключённые или удалённые в AD теряют доступ на ближайшей синхронизации (активные сессии обрываются). Ручная блокировка в админ-панели мессенджера синхронизацией не снимается. Права админа выдаются членам `LDAP_ADMIN_GROUPS`, включая вложенные группы.

Права пользователя видны в `/api/me`: `admin` — доступ к админ-панели мессенджера.

## 3. Мессенджер (`/messenger`)

- **Чаты**: личные (создаются автоматически между всеми активными пользователями) и групповые (создание, добавление/удаление участников, лимит участников).
- **Сообщения**: текст, вложения (со сканом ClamAV), ответы (reply), пересылка, редактирование, удаление («у себя» / «у всех»), реакции-эмодзи, закреплённые сообщения, поиск по переписке.
- **Статусы**: онлайн/отошёл/не беспокоить (авто + ручной, с истечением по времени), индикатор «печатает…», одинарная/двойная галочка прочтения.
- **Стикеры** и **обои чата** (загружаются пользователем).
- **Звонки**: 1:1 и групповые аудио/видео через LiveKit, история звонков по чату.
- **Уведомления**: заголовок вкладки браузера показывает счётчик непрочитанных.
- **Справочник «Люди»**: кнопка на левой панели — все сотрудники по отделам (ФИО, должность), поиск по ФИО, логину, отделу и должности; клик открывает личный чат. Пустые личные чаты в списке не висят — чат появляется, когда его открыли или в нём есть сообщения.
- **Поиск собеседника**: поле поиска чатов (от 2 символов) ищет и по сотрудникам — по ФИО, логину, отделу, должности.
- **Группы**: владелец переименовывает и удаляет группу, любой участник может выйти (права владельца переходят старейшему участнику) — меню «⋮» в шапке чата.

## 4. Десктоп-приложение мессенджера (`desktop/`)

Тонкая Electron-обёртка вокруг того же `/messenger` — не отдельный клиент,
функционал 1:1 с браузером (тот же Chromium). Исходники и подробная инструкция
по сборке/установке — `desktop/README.md`. Кратко:

```bash
cd desktop
npm install
npm start          # запуск в режиме разработки
npm run dist       # сборка инсталлятора под текущую ОС
```

При первом запуске — окно настроек с адресом сервера (по умолчанию
`https://192.0.2.8`, как в `.env`), дальше — одноразовое подтверждение
самоподписанного сертификата и обычный логин.

Единственное новое поведение по сравнению с браузером — статусы присутствия:
закрытие окна прячет его в трей вместо выхода, поэтому страница (и её
heartbeat) продолжают работать в фоне. Это даёт полноценное **«отошёл»**
(комп включён, окно свёрнуто/не в фокусе) в дополнение к «в сети»/«не в сети» —
бэкенд ничего не менял, он и раньше умел брать статус по всем подключениям
пользователя сразу, поэтому десктоп и открытая параллельно вкладка браузера
автоматически показывают один согласованный статус. «Не в сети» — только
когда приложение закрыто через «Выход» в трее или сам компьютер выключен.
Для «отошёл», который держится с самой загрузки компьютера, а не с момента
ручного запуска — включите в трее «Запускать при входе в систему».

## 5. Админ-панель мессенджера

Открывается из мессенджера (иконка администратора, видна только роли `admin`). Вкладки:

| Вкладка | Что делает |
|---|---|
| Общее | глобальный тумблер звонков, максимальный размер вложения |
| Пользователи | тихий режим (запрет отправки), доступ к звонкам, включить/отключить учётку, отозвать сессии |
| Журнал аудита | лента событий (вход, изменения прав, звонки и т.п.), поиск, экспорт в CSV |
| Хранение данных | сроки хранения сообщений/файлов/журнала/бэкапов |
| Лимиты | rate-лимиты (сообщения/мин, логины/час), максимум участников группы, приглашений в день |
| Аудиторы | роль `security_auditor` — читает журнал и метаданные, но не содержимое переписки |

## 6. Переменные окружения — важное (`.env`)

| Переменная | За что отвечает |
|---|---|
| `DATABASE_URL`, `POSTGRES_PASSWORD` | подключение к Postgres |
| `AI_FLASK_SECRET` | секрет сессий платформы (обязателен в проде) |
| `ALLOW_ANONYMOUS` | анонимный вход без логина — только не-Docker локальный запуск; в docker-compose всегда `false` |
| `MESSENGER_JWT_PRIVATE_KEY` / `MESSENGER_JWT_PUBLIC_KEY` | пара Ed25519-ключей для JWT мессенджера — сгенерировать: `python scripts/generate_messenger_keys.py` |
| `MESSENGER_LIVEKIT_*` | подключение к серверу звонков |
| `LDAP_*` | параметры Active Directory |

Полный список — `.env.example`, там же комментарии на русском по каждому блоку.

## 7. Обслуживание и типичные проблемы

- **После `docker compose up` нет доступа к https://localhost с хоста** — если на машине включён VPN (в частности Mullvad), убедитесь что разрешена локальная сеть: `mullvad lan set allow`. Иначе TCP-соединение до контейнеров рвётся сразу после handshake.
- **Правки в `.py`/`.js`/`.css` не видны после `docker compose restart`** — нужна пересборка образа (см. раздел 1), `restart` код не обновляет.
- **Правки в `deploy/nginx*.conf` не подхватываются** — на этой машине помогает только `docker compose up -d --force-recreate gateway`, не `reload`/`restart`.
- **Шлюз падает с `Permission denied` на `/run/tls/privkey.pem`** — права на файл слишком строгие для непривилегированного nginx: `chmod 644 deploy/tls/privkey.pem`, затем пересоздать `gateway`.
- **Резервное копирование**: сервис `services/backup` — см. `services/backup/backup.sh` / `restore.sh`.
